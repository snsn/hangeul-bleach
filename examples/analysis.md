# 문법·문체·스타일 통합 분석 예시

[원문](before.md)을 [수정본](after.md)으로 다듬은 사례다. 아래 선택은 이 예제에만 적용하며 모든 문서의 표준이 아니다.

## 검토 범위와 기준

- 범위: 백업 안내 전체. 제목, 본문, 절차, 일정, 도움말을 검토했다.
- 독자·목적: 사용자가 백업과 복구 기능을 이해하고 절차를 따라 하는 안내문.
- 기준: 일반 설명과 절차는 합니다체, 계정 주체는 ‘사용자’, 단위 기호 앞 공백, 날짜는 연-월-일, 시각은 24시간제로 정리한다.
- 보호 대상: 로그의 직접 인용, 설정 키, URL, 수치, 실패 가능성과 부정문.
- 이 기준은 예제의 문서 내 통일안이다. 국어 규범이나 특정 기관이 이 형식을 의무화한다고 주장하지 않는다.

## 발견 사항

### C1. 어조와 격식 — 통일 권장

- 위치: 첫 문단의 둘째 문장.
- 원문: ‘볼 수 있어요’.
- 수정: ‘볼 수 있습니다’.
- 근거: 같은 기능 설명 안에서 합니다체와 해요체가 섞였다. 인접 설명문의 문체에 맞춘다.
- 보존: ‘볼 수 있다’의 기능·가능 의미를 유지했다.

### C2. 같은 개념의 표기 — 통일 권장

- 위치: 첫 문단과 둘째 문단.
- 분포: 일반 설명문에 ‘유저’ 1회, ‘사용자’ 1회. 코드 식별자는 집계에서 제외했다.
- 수정: ‘유저’ → ‘사용자’.
- 근거: 두 문장 모두 백업 기능을 이용하는 같은 주체다. 동률이므로 빈도에 의한 선택이 아니라 이 문서의 한국어 설명에 맞춘 선택이다.
- 예외: `backup_user`는 용어 통일 대상이 아니다.

### G1. 의존 명사 띄어쓰기 — 오류

- 위치: 둘째 문단.
- 원문: ‘확인할수있습니다’.
- 수정: ‘확인할 수 있습니다’.
- 근거: 의존 명사 ‘수’를 앞말과 띄어 쓴다.

### N1. 목적어를 우회하는 표현 — 문체 제안

- 위치: 둘째 문단.
- 원문: ‘백업 파일에 대해 확인할 수 있습니다’.
- 수정: ‘백업 파일을 확인할 수 있습니다’.
- 근거: 파일이 확인의 직접 대상이므로 목적어로 연결해도 뜻이 같다.
- 예외: ‘백업 정책에 대해 어떻게 생각하나요’처럼 의견의 대상을 뜻하면 동일하게 고치지 않는다.

### C3. 단위 간격 — 통일 권장

- 위치: 저장 공간과 업로드 한도 설명.
- 분포: ‘500MB’는 붙임, ‘2 GB’는 띄움.
- 수정: ‘500MB’ → ‘500 MB’.
- 근거: 같은 종류의 단위 표기에서 공백 사용을 맞춘다. 모든 띄어쓰기 차이가 맞춤법 오류라는 뜻은 아니다.
- 보존: 500, 2, MB, GB를 유지하고 단위 환산이나 반올림은 하지 않았다.

### N2. 피동과 명사화 — 문체 제안

- 위치: 백업 검증 설명.
- 원문: ‘서비스에 의해 백업 검증의 수행이 이루어집니다’.
- 수정: ‘서비스가 백업을 검증합니다’.
- 근거: 행위자가 원문에 명시되어 있으므로 능동문으로 바꿀 수 있다. ‘검증의 수행’은 ‘검증하다’로 풀었다.
- 집계: 하나의 문장 구조를 고친 항목으로 묶었다. 피동과 명사화를 별도 오류 두 건으로 세지 않았다.

### C4. 절차의 병렬성 — 통일 권장

- 위치: 복구 절차 1번과 3번.
- 원문: ‘백업 선택’, ‘완료 여부를 확인하세요’.
- 수정: ‘백업을 선택합니다’, ‘완료 여부를 확인합니다’.
- 근거: 같은 수준의 절차를 합니다체로 맞춘다. 이 문서는 절차를 순서대로 설명하는 방식으로 정리했다.
- 보존: 항목 수와 1 → 2 → 3의 순서를 유지했다. ‘백업 선택’ 자체를 문법 오류로 처리하지 않는다.

### C5. 날짜 형식 — 통일 권장

- 위치: 점검 일정 첫 문장.
- 분포: ‘2026.10.05’와 ‘2026-10-06’.
- 수정: ‘2026.10.05’ → ‘2026-10-05’.
- 근거: 연월일이 모두 분명한 두 날짜의 구분 기호를 맞춘다.
- 예외: ‘10/11’은 연도와 월·일 순서가 명확하지 않아 유지했다.

### C6. 시각 형식 — 통일 권장

- 위치: 점검 시작·종료 시각.
- 원문: ‘오후 3시’와 ‘18:00’.
- 수정: ‘오후 3시’ → ‘15:00’.
- 근거: 오후가 명시되어 있어 같은 시각을 24시간제로 표현할 수 있다.
- 보존: 시간대를 추가하거나 시차를 환산하지 않았다.

### C7. 링크 설명 — 통일 권장

- 위치: 도움말 첫 문장.
- 원문: ‘[여기](https://example.com/backup)’.
- 수정: ‘[백업 안내 문서](https://example.com/backup)’.
- 근거: 원문이 링크를 백업 안내라고 설명하므로 대상이 드러나는 문구를 쓸 수 있다. 외부 페이지의 실제 제목을 확인했다고 주장하지 않는다.
- 보존: URL은 그대로다.

## 수정하지 않은 항목

| ID | 위치·표현 | 판단 | 이유 |
| --- | --- | --- | --- |
| K1 | ‘실패할 수 있습니다’ | 유지 | 가능성을 단정으로 바꾸면 의미가 달라짐 |
| K2 | ‘복구가 되요’ | 유지 | 실제 로그의 직접 인용이므로 맞춤법 교정 대상에서 제외 |
| K3 | `backup_user` | 유지 | 실제 설정 키이므로 사용자 용어와 별도 취급 |
| K4 | ‘삭제되지 않습니다’ | 유지 | 부정 의미 보존 |
| K5 | 번호 목록 | 유지 | 순서가 있는 절차이므로 글머리표로 바꾸지 않음 |
| Q1 | ‘10/11’ | 확인 필요 | 연도와 날짜 순서를 원문만으로 확정할 수 없음 |

확인 질문: ‘추가 점검일 10/11의 연도와 월·일 순서는 무엇인가요?’ 답변 전에는 이 부분만 그대로 두고 나머지 교정을 완료할 수 있다.

## 집계와 우선순위

| 분류 | 발견 항목 수 | 처리 |
| --- | ---: | --- |
| 문법 | 1 | G1 수정 |
| 문체 | 2 | N1–N2 수정 |
| 일관성 | 7 | C1–C7 수정 |
| 유지 | 5 | K1–K5 변경 없음 |
| 확인 필요 | 1 | Q1 원문 유지 |

수정한 발견 항목은 10개다. 이는 문자열 교체 횟수가 아니다. 유지한 항목과 미확정 날짜를 오류 수에 포함하지 않았다. 문법 오류와 날짜의 모호함을 먼저 확인하고, 용어·어조·문장 구조와 표시 형식을 정리했다.

## 이번 문서에 적용한 스타일 규칙

| 대상 | 선택 | 예외 |
| --- | --- | --- |
| 설명과 절차 | 합니다체 | 직접 인용 |
| 기능 이용 주체 | 사용자 | 코드 식별자 |
| 단위 기호 | 숫자와 공백 | 코드 값 |
| 확정된 날짜 | YYYY-MM-DD | 정보가 부족한 날짜 |
| 시각 | HH:mm | 시간대는 원문 유지 |
| 링크 | 대상이 드러나는 설명 | URL은 보존 |

## 의미 보존 확인

원문과 수정본의 백업 생성 주기, 저장 공간, 업로드 한도, 검증 주체, 복구 절차 순서, 실패 조건과 가능성, 확정된 날짜와 시각을 대조했다. 인용, 설정 키, URL과 마지막 문장의 부정도 유지했다. 이 대조는 문서에 적힌 기능이 실제 제품에서 구현되었음을 검증하는 작업은 아니다.
