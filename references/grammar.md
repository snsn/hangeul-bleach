# 문법·맞춤법 검토

DaleSeo/korean-skills의 grammar-checker를 바탕으로 개발 문서에 맞게 재구성했다. 출처와 적용 범위는 ../THIRD_PARTY_NOTICES.md 참조.

## 검사 순서

명백한 맞춤법 오류, 띄어쓰기, 조사·어미와 문장 호응, 문장부호 순으로 검토한다. 확실한 오류와 문체상 권장을 구분한다. 규칙이 불확실하면 국립국어원 사전·어문 규정을 확인하고, 확인하지 못한 사항을 규범 위반으로 단정하지 않는다.

## 맞춤법과 형태

- 되/돼: ‘되어’로 풀어 쓸 수 있는지 확인한다. ‘되요’는 ‘돼요’, ‘됬다’는 ‘됐다’로 고친다.
- 안/않: 부사 ‘안’과 ‘-지 않다’를 구분한다. ‘실행하지 안는다’는 ‘실행하지 않는다’로 고친다.
- 던/든: 과거 회상과 선택을 구분한다. ‘사용하던 설정’과 ‘어느 쪽이든’은 뜻이 다르다.
- 로서/로써: 자격·지위와 수단·도구를 구분한다. 문맥 없이 서로 치환하지 않는다.
- 어미: ‘좋은지’와 ‘작동하는지’처럼 품사와 활용을 확인한다. 받침 하나만으로 모든 활용을 판정하지 않는다.
- 웬/왠, 어떻게/어떡해 등 혼동되는 표현도 문장 속 의미를 확인한다.

## 띄어쓰기

- 의존 명사는 앞말과 띄어 쓴다. ‘할수있다’ → ‘할 수 있다’, ‘하는것’ → ‘하는 것’.
- 같은 형태의 조사·어미와 구분한다. ‘설치하는 데 시간이 걸린다’와 ‘설치하는데 오류가 난다’, ‘확인한 지 오래됐다’와 ‘완료했는지 확인한다’는 구조가 다르다.
- 보조 용언은 허용 범위를 확인한다. 일부 붙여쓰기가 허용된다고 모든 보조 용언을 붙이지 않는다. ‘처리하고 있다’를 ‘처리하고있다’로 바꾸지 않는다.
- 숫자와 단위의 허용 표기를 문법 오류로 몰지 않는다. 문서의 표기 기준에 맞추되 코드 값, 버전, 제품명, 수식은 보존한다.
- 합성어와 전문 용어는 사전 및 문서 용어집을 확인한다. 단어를 무조건 쪼개거나 합치지 않는다.

## 조사·호응·부호

- 한글·영문·숫자 뒤의 조사는 읽는 발음과 문장 기능을 함께 확인한다. ‘으로/로’는 ㄹ 받침 예외도 고려한다.
- 긴 문장에서 주어와 서술어, 목적어와 동사의 호응을 확인한다. 문장을 나눌 때 조건이나 예외의 적용 범위가 달라지지 않게 한다.
- 시제는 현재 동작, 과거 결과, 미래 계획에 맞게 유지한다.
- 괄호와 따옴표의 짝, 문장 경계, 열거의 구분을 확인한다. 제목과 명사형 표 항목에 완전한 문장이나 마침표를 강제하지 않는다.
- 쉼표와 가운뎃점은 의미 구분과 가독성을 기준으로 판단한다. 사용 횟수나 특정 문형만으로 오류로 처리하지 않는다.

## 결과 설명

검토 보고를 요청받으면 ‘위치 / 수정 전후 / 이유 / 확실한 오류 또는 권장 사항’을 간결하게 제시한다. 학습 목적일 때만 관련 규칙과 추가 예시를 자세히 설명한다. 파일 수정 요청에서는 모든 교정에 장문의 설명을 붙이지 않는다.
