# 상세 판단 규칙과 예외

전체 문서 리뷰에서는 이 표의 범주를 빠짐없이 확인한다. 발견되지 않은 문제를 만들 필요는 없다. 각 예문은 가상의 문맥이며 프로젝트 용어집이나 공식 표기를 대신하지 않는다.

## 문법: 형태와 띄어쓰기

| 항목 | 확인 방법과 교정 예 | 예외·경계 |
| --- | --- | --- |
| 되/돼 | ‘되어’로 풀어 확인: 저장이 되요 → 저장이 돼요 | ‘되면’처럼 어간 뒤 어미가 붙는 형태까지 바꾸지 않음 |
| 안/않 | 부사와 ‘-지 않다’ 구분: 실행하지 안는다 → 실행하지 않는다 | ‘안되다’의 사전적 의미와 단순 부정을 문맥으로 구분 |
| 던/든 | 회상: 사용하던 값 / 선택: 어느 값이든 | 과거 사실과 선택 조건을 서로 바꾸지 않음 |
| 로서/로써 | 자격과 수단을 구분: 관리자로서, 도구로써 | 간단한 ‘로’가 자연스러워도 의미 관계는 유지 |
| 지 | 완료했는지 확인 / 완료한 지 하루 | 어미와 경과 시간을 나타내는 의존 명사를 구분 |
| 데 | 처리하는 데 필요 / 처리하는데 실패 | 용도·상황 명사와 연결 어미를 구분 |
| 뿐·만큼·대로 | 읽을 뿐 / 설명한 만큼 / 정한 대로 | ‘문서뿐’, ‘예전만큼’, ‘규칙대로’의 조사는 붙임 |
| 수·것·줄 | 할수있다 → 할 수 있다 | 문자열이나 식별자 내부는 검사 대상에서 제외 |
| 보조 용언 | 확인해 주세요 / 처리하고 있다 | 모든 보조 용언에 붙여쓰기를 허용하지 않음 |
| 조사 | 책를 → 책을, 파일으로 → 파일로 | 영문 약어는 발음 확인, ㄹ 받침의 ‘로’ 예외 |
| 호응 | ‘이유는 실패했다’처럼 주어와 서술어가 안 맞는지 확인 | 원인 설명이 없으면 원인을 만들어 보충하지 않음 |
| 부정 범위 | ‘모두 허용하지 않는다’의 전체·부분 부정 확인 | 뜻이 모호하면 임의로 ‘아무것도’나 ‘일부만’으로 바꾸지 않음 |
| 수식 범위 | 조건절이 어느 동작까지 적용되는지 확인 | 문장을 나누며 예외 조건이 한쪽에만 붙지 않게 함 |
| 문장부호 | 따옴표·괄호의 짝과 열거 경계 확인 | 명사형 제목과 표 셀에 마침표를 일괄 추가하지 않음 |

상세한 문법 설명이 필요하면 [문법 기준](grammar.md)을 함께 사용한다. 표에 없는 활용이나 사전 등재 여부가 불확실하면 공식 사전·규정을 확인한다.

## 문체: 반복과 번역투

| 항목 | 검토 단서 | 교정 방향 | 유지해야 하는 경우 |
| --- | --- | --- | --- |
| 쉼표 | 짧은 주어·서술어 사이의 쉼표 | 불필요한 끊김 제거 | 삽입구, 긴 열거, 의미 구분 |
| 콜론·괄호 | 문장마다 설명이 분절됨 | 본문 문장으로 연결 | 정의, 값 목록, 보충 정보 |
| 명사화 | 수행·진행·실시의 중첩 | 실제 동사로 표현 | 전문 용어 자체가 명사인 경우 |
| 추상 수식 | ‘효율적인 체계적 개선’ 등 | 원문이 설명한 동작으로 구체화 | 새로운 효과나 측정값을 만들지 않음 |
| 강조 | 매우·핵심·혁신의 반복 | 정보 없는 수식만 덜어냄 | 인용, 주장 강도, 제품의 공식 명칭 |
| 지시어 | 해당·이러한·그것의 반복 | 대상 이름 또는 생략 | 대상이 달라지거나 지시가 필요한 경우 |
| 복수형 | 모든 명사 뒤의 ‘들’ | 수량 의미가 중복되면 조정 | 집합·개별 대상의 차이가 필요한 경우 |
| 주어 | 매 문장 같은 주어 반복 | 명확할 때만 생략 | 행위자 전환, 책임 주체의 명시 |
| 연결어 | 또한·그리고·따라서가 연속됨 | 관계를 유지하며 통합 | 대조·인과가 약해지는 경우 |
| 문장 리듬 | 같은 구조가 기계적으로 반복됨 | 논리 단위에 맞춰 분리·결합 | 문법적 병렬성이 필요한 절차 |
| 목록 길이 | 내용 없이 항목 수만 맞춤 | 실제 정보 단위에 맞춤 | 세 항목이라는 이유만으로 삭제·추가하지 않음 |
| 결론 | 새 정보 없이 본문과 같은 문장 반복 | 필요한 요점만 남김 | 독립적으로 읽는 요약과 요구된 결론 |
| 에 대해 | 목적어를 간접적으로 표현 | 로그에 대해 분석 → 로그를 분석 | 태도·의견의 대상 |
| 통해 | 같은 매개 표현 반복 | 도구를 통해 확인 → 도구로 확인 | 실제 경유·전달 과정 |
| 있어서 | 영역을 장황하게 표현 | 처리에 있어서 → 처리에서 | 존재를 뜻하는 ‘파일이 있어서’ |
| 관련 | 관계의 종류가 불명확함 | 원문에 있는 직접 관계로 표현 | 관련 항목과 소속 항목의 차이 |
| 기반 | 근거·준수·재료를 구분 안 함 | 정확한 관계에 맞춰 풀어 씀 | 기반 기술의 의미가 중요한 경우 |
| 가지고 있다 | 속성을 소유처럼 표현 | 권한을 가지고 있다 → 권한이 있다 | 소유·보유 행위가 핵심인 경우 |
| 이중 피동 | 되어진다 등의 중복 | 변경되어진다 → 변경된다 | 사역과 피동이 별개 의미인지 확인 |
| 에 의해 | 행위자가 뒤로 밀림 | 도구에 의해 생성 → 도구가 생성 | 행위자 불명, 대상 중심 설명 |
| 위해 | 목적 표현이 중첩됨 | 확인을 하기 위해 → 확인하려고 | 목적과 조건을 혼동하지 않음 |
| 가능·미래 | 할 수 있다·할 것이다 반복 | 문장 구조만 간결하게 조정 | 능력·허용·가능성·예측의 강도 보존 |
| 점에서 | 이유와 평가 범위를 우회함 | 이유이면 연결 어미 검토 | ‘비용 면에서’처럼 평가 범위 한정 |

빈도는 재검토할 위치를 찾는 데 사용한다. 정해진 횟수를 넘었다고 강제 수정하거나 AI가 쓴 글이라고 판정하지 않는다.

## 스타일: 일곱 범주의 세부 기준

### 어조와 서술 관점

종결형, 호칭, 우리·저희·사용자 등의 서술 관점을 비교한다. 고객 대상이라는 이유만으로 저작권자나 회사 공식 명칭을 겸양 표현으로 바꾸지 않는다. 안내문 속 명령형과 기능 설명 속 평서형은 역할이 다르면 공존할 수 있다. 명사형 제목을 미완성 문장으로 취급하지 않는다.

### 용어와 약어

같은 개념인지 먼저 확인하고 대표 표기를 선택한다. 화면·페이지·UI, 저장·보관·백업은 문맥에 따라 서로 다르다. 약어를 처음 설명한 뒤 약어만 쓰는 구성은 정상이다. 공식 제품명과 코드 대소문자를 보존하고, 전문 용어를 순화하려다 정의가 바뀌지 않게 한다.

작업용 용어표: `개념 / 원문 변형 / 채택 표기 / 근거 / 예외 위치`. 표기 빈도를 기재할 경우 일반 설명문과 코드의 집계를 분리한다.

### 숫자와 단위

같은 종류의 수치끼리 형식을 비교한다. 연도·버전·포트·오류 코드는 일반 수량과 구분한다. ‘한두 번’ 같은 근사 표현을 정확한 숫자 범위로 바꾸지 않는다. 천 단위 구분이나 단위 간격은 해당 문서 규칙에 맞추며, 값·정밀도·단위 종류를 유지한다. GB와 GiB, 비율과 퍼센트포인트를 표기 변형으로 취급하지 않는다. SI 규정 준수를 요청받으면 실제 규정을 확인하고 일반 문서의 관행과 구분한다.

### 목록 구조

목록별 목적을 구분한다. 절차는 순서가 있는 번호, 단순 열거는 글머리표가 적절하다. 같은 수준에서만 부호·들여쓰기·종결형을 맞춘다. 하위 항목을 상위로 옮기거나 번호를 고치면서 분기 조건을 잃지 않는다. 기능 목록은 명사형, 절차는 행동을 나타내는 문장처럼 역할별 기준을 둘 수 있다.

### 인용과 강조

직접 인용, 용어 소개, 강조, 코드의 용도를 먼저 구분한다. 큰따옴표와 작은따옴표가 함께 있다는 사실만으로 불일치가 아니다. 강조 수준이 같을 때 표현을 맞추고 코드 백틱을 장식용 굵게로 바꾸지 않는다. 경고 아이콘 제거로 의미가 사라지지 않게 한다. 실제 인용 내용은 그대로 둔다.

### 날짜와 시간

연월일이 모두 분명한 날짜는 선택한 표시 형식으로 통일할 수 있다. 빠진 연도·시간대는 추정하지 않는다. 12시간제와 24시간제 변환은 오전·오후가 확실할 때만 한다. 기간과 시각, 마감 포함 여부를 구분한다. 표기 통일을 이유로 UTC를 현지 시간으로 환산하지 않는다.

### 링크와 참조

‘여기’보다 대상이 드러나는 링크 설명을 검토하되 페이지 제목을 모르면 지어내지 않는다. 참조 번호를 변경한다면 본문의 호출 위치와 각주 목록을 함께 대조한다. 누락된 저자·연도·출처를 만들어 채우지 않는다. 자동 앵커, 명시적 ID, 링크 URL과 인용문의 출처 관계를 유지한다.

## 문서 목적에 따른 적용

| 목적 | 우선 확인 | 허용할 차이 |
| --- | --- | --- |
| 개발자 안내 | 개념·식별자, 조건과 절차, 코드·링크 | 역할별 명사형 제목과 명령형 절차 |
| 기술 보고서 | 수치·단위, 관찰 결과와 추정, 근거 | 인용과 본문 어조 |
| 학술 설명 | 정의, 인용 형식, 가설과 결론 | 원어 병기와 정의 이후 약어 |
| 제품 안내 | 독자가 이해할 용어, 기능과 홍보의 구분 | 브랜드 문구·UI 문자열 |
| 기술 블로그 | 작성자 목소리, 설명의 흐름, 전문 용어 | 의도적인 구어체와 질문 |

이 표는 문체 선택의 근거를 찾는 기준이다. ‘공식 문서는 무조건 특정 종결형’ 같은 규칙을 새로 만들지 않는다.
